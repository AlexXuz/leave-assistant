# Day26 · 提示与验收讨论

本页不提供毕业项目答案，也不替学习者填写个人草稿。先录制自己的演示与解释，再按需要查看提示。

## 提示一：用一条任务串起证据

选自己实际做过的客服任务，沿请求编号追踪 Python 服务、模型决策、工具观察、结果和引用。再展示一个新领域任务，指出哪些组件复用，哪些工具和成功条件重设计。每一处“完成”都应能对应真实状态或产物。

原 OA 项目可以证明 RAG、事务、授权等基础，不能替代独立 Agent 和跨领域交付。MCP、Skill、LangGraph是可选组合方式，要能解释选择理由，而不是只报框架名称。

## 提示二：把演示切成四种问题

- 功能：目标是否完成，缺信息或证据矛盾时怎样处理？
- 工程：Python 异步等待、同步阻塞、并发限制、超时与取消如何实现？
- 可靠性：worker 退出后怎样恢复，外部已写但检查点未存时怎样避免重复？
- 效果：同任务重复运行稳定吗，哪里失败，优化换来了多少成本与延迟？

先准备可打开的代码和逐任务记录。自己不知道的部分直接列为缺口，不能靠补写一段说明充当运行证据。

## 提示三：先观察事实，再决定恢复

工具成功、模型解释失败时先读业务状态。外部动作结果不确定时先按稳定动作 ID 查询。旧人工决定或身份变化应重新校验，不从历史摘要推断授权。取消等待不自动撤销已发出的远端动作。

部署故障也按层定位：配置与依赖、网络、模型服务、业务工具、持久状态、展示。发布/回滚必须记录具体版本与结果，镜像构建通过本身不是部署验收。

## 提示四：检查报告有没有混淆验证范围

模拟模型与真实模型分别报告；live 参数只是标签。公开练习集不能当秘密留出，人工语义尚未审核不能改称任务成功。usage 缺失不计零成本，少量样本的 p95 不代表生产 SLA。微型随机模型训练只证明训练机制，不代表业务微调收益。

## 五项硬标准

- **D26-C1**：本人 Python Agent 从目标到结果，能解释异步、超时与取消。
- **D26-C2**：客服和新领域迁移，并完成真正未练过的需求变化。
- **D26-C3**：身份、证据、人工决策、事务/幂等和恢复，无关键违规。
- **D26-C4**：真实模型重复评测、简单基线、逐任务事实及成本延迟可复核。
- **D26-C5**：独立部署、发布/回滚和真实 worker 故障恢复可复现。

具体口径以[任务书](../tasks/independent_final_demo.md)为准。前两门和 Day25 必须通过；关键项不能靠总分抵消。检查器核验记录结构和哈希，语义、独立性和运行真实性仍须复核。

## 完整示范与辅助的边界

本课没有自动完成整项任务的参考程序。允许使用工具和 AI，但要说明哪些代码和决定由辅助完成，并能自己修改、解释和验证。看过完整同题实现后另换新要求验证迁移。见[证据规则](../EVIDENCE_PROTOCOL.md)。
