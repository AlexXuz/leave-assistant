# Day11 · 分级提示与验收讨论

先独立尝试，不在这里提供完整接线答案。

## 提示一：明确输入输出

prepare_application(text, services)只生成草稿；confirm_application(draft_id, revision, services)绑定用户看过版本；submit_application(draft_id, revision, key, services)复查状态和幂等，同key只返回原结果。支持范围外先说明，不硬套年假额度。

## 提示二：逐层观察

自然语言提取 → 后端预检/草稿版本 → 用户明确确认 → 提交复查/事务 → 一笔待审批申请 → 读回业务状态。

指出每一层的对象类型、可信来源和失败语义，不把模型文本当业务事实。

## 提示三：从失败反推缺口

SQL成功后模型说明超时，读回原申请并用同key恢复说明；事务中失败则无部分预占，不能把两类故障混成未提交。

- **D11-C1**：确认绑定身份/版本/内容，确认不等于提交。
- **D11-C2**：提交原子、余额复查、幂等与并发拒绝有真实证据。
- **D11-C3**：已提交后失败仍保留业务事实，不重复建单或预占。
