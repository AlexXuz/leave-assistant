# Day7 · 分级提示与验收讨论

先独立尝试，不在这里提供完整接线答案。

## 提示一：明确输入输出

synchronize_source(snapshot, store, embedder)规划后再事务应用，失败回滚；prepare_visible_request(question, trusted_access, store, top_k)从服务端身份派生来源/部门范围，过滤后再排名。

## 提示二：逐层观察

同来源完整快照 → 同步计划 → 事务/版本复查 → 更新片段与清单 → 权限SQL过滤 → TopK → 授权消息。

指出每一层的对象类型、可信来源和失败语义，不把模型文本当业务事实。

## 提示三：从失败反推缺口

事务中途失败后读不到半成品；旧批次遇到更新后的来源必须冲突。重新规划同快照可以成功，不重复编码不变正文。

- **D7-C1**：完整快照、来源隔离、版本检查与原子回滚有证据。
- **D7-C2**：检索前权限过滤，未知身份不扩大范围。
- **D7-C3**：授权命中才进入模型，过期/删除文档不残留。
