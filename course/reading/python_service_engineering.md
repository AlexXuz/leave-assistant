# Python AI 服务工程：从已有后端经验到独立交付

适用Day16–18，也作为Day19/24服务实现的查阅页。目标是能用Python交付与排障，不要求先重学所有通用后端知识。阅读路线：先看自己实现所需的小节，做出运行证据后再补下一项。

## 1. 模块、配置与可替换依赖

将API/schema、应用协调、外部适配器、运行配置分开。Python模块导入会执行顶层语句；导入时读生产凭证、联网或启动worker会使测试和命令工具难以复用。把初始化放到明确的应用工厂/lifespan里，让导入本身无外部副作用。

配置从环境映射创建类型对象，验证必填项与范围。凭证字段隐藏repr，日志仍要主动控制输出；隐藏repr不能阻止手动序列化泄密。不要为方便调试把整个配置对象写进JSON响应。

测试通过显式参数或依赖工厂注入模型/工具替身。替身负责可重复的错误路径，真实网络请求负责验证协议和环境。两者分别记录，不能用测试替身的固定答案证明模型效果。

## 2. 类型帮助理解，校验负责边界

Pydantic用于请求、工具参数和外部输出的运行时校验。dataclass适合内部状态，TypedDict适合描述既有字典，Protocol描述依赖的调用形状。注解本身不保证数据安全；无论哪种类型，可信身份、权限和业务确认仍须由后端来源决定。

模型输出解析、参数schema校验、工具授权、业务规则是不同层级。把错误分类到来源，调用者才能决定重试、追问、拒绝或人工处理。不能靠一个大异常捕获把所有失败改成“暂无数据”。

## 3. I/O、并发和取消

异步适合在等待网络/数据库时把执行权交给其他任务。同步阻塞函数放进async函数不会自动让出执行权。优先异步驱动；暂时的线程隔离要说明取消和线程池容量限制。纯Python CPU密集计算通常需要另行考虑进程或外部执行服务，不能只增加协程数。

为每个任务画两种限制：并发槽位控制同时执行数量；deadline控制从入场到退出的总等待。重试与排队都消耗总期限。工具级连接/读取/数据库语句期限仍需设置，因为协程取消不等于远端动作撤销。

Python 3.11 TaskGroup能把一组任务放在共同生命周期内，错误会触发同组取消与收尾。处理预期工具失败时保留结构化错误；处理取消时清理资源并传播，不吞掉CancelledError。后台任务必须有明确所有者，不能随手create_task后丢掉引用、异常和关闭逻辑。

## 4. HTTP客户端、流与应用生命周期

在lifespan中建立应用级HTTP客户端等资源，由上下文管理器保证退出关闭。请求身份属于请求，不能放共享可变字段。客户端连接池、供应商限流和任务并发上限要共同考虑，避免任务数看似有限但连接长期耗尽。

流式响应须关闭上游流，即使客户端取消或解析失败。浏览器断线、用户取消、服务停机三者分别建模。SSE至少记录持久事件ID、任务归属和终态，重连是读取缺失事件，不重新创建业务动作。

## 5. 可观察与可验证

一条run跨多个HTTP请求与模型/工具步骤。保留request_id、run_id、tool_call_id和业务编号的关联，记录脱敏参数、版本、阶段耗时及错误。并发步骤耗时之和不能代表用户等待时间。

usage缺失标unknown，估算另列；超时和语义失败分开统计。对安全边界检查实际工具动作与业务状态，对回答质量检查证据与结论。历史轨迹可重算评分，不应默认重新执行写工具。

## 6. 可复现部署与验证边界

交付锁定依赖、Python版本、启动模块、容器配置、健康/就绪端点、数据持久化路径和恢复方法。用独立环境演示本人API，记录镜像标识；不要把本机.env或权重复制进镜像以“方便启动”。

Day16完成本机容器和资源生命周期；Day17完成异步执行与重连；Day18完成故障和成本记录；Day24验证Agent重启与幂等恢复；Day26进行隔离部署的访问控制、真实链路与回滚。分阶段证据不能互相冒充，没执行的范围保持未执行。
