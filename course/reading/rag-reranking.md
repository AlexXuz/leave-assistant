## 2. 区分候选缺失和排序丢失

最终需要两条证据，检索却可以先取六条候选。诊断有两种主要情况：

| 情况 | 例子 | 下一步考虑 |
| --- | --- | --- |
| candidate_missing | 必要片段完全不在候选六条中 | 改善召回、切分、查询或候选策略 |
| ranking_loss | 必要片段在候选中，但排在第三至第六，未进入最终两条 | 可以尝试重排 |
| covered | 最终两条已经覆盖必要证据 | 还需另验生成和引用质量 |

同一个案例可能同时有“某条必要证据没进候选”和“另一条进了却没选中”；报告分别保留 candidate_missing、ranking_loss 布尔值。diagnosis 字段优先显示候选缺失，不能只看字符串忽略另一种损失。

重排从已有候选中选，不会产生新的片段。RRF 池本轮也限制为六条：每路先取六条，RRF 合并后留下六条，再从中选两条。模型重排时会拿同一批 RRF 六条候选比较，避免同时改召回范围和排序方式。

已跑出的首次基线是 reports/retrieval-lab-v2-20261018-112435-358398.json。向量、BM25、RRF 最终找齐必要证据的题数为 27/30、23/30、27/30，平均必要证据召回率分别为 93.33%、78.33%、91.67%。候选找齐分别为 30/30、28/30、30/30。

具体例子：paraphrase_receipts 问“外地办完事回来了，住店花的钱想找公司报，要交哪些单子？”RRF 前六名是返程结算、居家设备补助、申请与凭证、已批年假撤销、餐费报销材料、远程内网账号。必要证据是第三名“申请与凭证”，正文明确要求住宿发票和订单记录。它在候选中，最终取两条时却丢失，属于 ranking_loss。尚未使用真实重排模型，不提前宣称能修复。

## 3. Cross-Encoder 如何打分

已有 Embedding 流程分别编码问题和片段，再计算向量相似度；文档向量可以提前存入索引。

Cross-Encoder 的输入是一个文本对：

```text
(问题, 某个候选片段正文) → 模型联合读取 → 一个相关性分数
```

对于六个候选，需要六对输入，可以一次批量传给模型。片段和问题会一起参与计算，因此它不能直接复用原来的文档向量作为重排分数。联合计算一般更费时，通常用在召回之后的一小批候选上。

它输出相关性分数，不生成最终业务回答，也不自动证明答案受制度支持。分数的范围取决于模型和输出设置，不能一律当作正确率或套用余弦阈值。是否改善，仍由同一候选池上的结果判断。

RRF 只综合已有榜单的排名；Cross-Encoder 会重新读取问题与片段正文。这是两者工作方式的差别。

官方说明：https://sbert.net/examples/cross_encoder/applications/README.html

## 4. 本轮只实现 rerank_candidates

文件 app/reranking.py。模型加载和下载后续由助教处理，这一轮先把业务接线写清楚，不需要自己实现神经网络。

函数参数：

- question：原问题字符串。
- candidates：已去重的候选列表，每项仍是 {chunk, score}。
- score_pairs：评分函数，输入 [(问题, 正文), ...]，输出同顺序分数。
- top_k：最终取几条。

score_pairs 是函数对象，可类比 Java 的 Function。你负责准备输入并调用它；后续会把真实模型评分函数传进来。固定评分器只用于离线验证数据与分数是否关联正确。

示例：

```text
候选原顺序：A、B、C
组装输入：[(问题, A正文), (问题, B正文), (问题, C正文)]
评分返回：[0.2, 0.9, 0.4]
排序结果：B、C、A
top_k=2：返回 B、C
```

实现顺序：

1. top_k < 1 抛 ValueError；空候选直接返回 []，不调用评分器。
2. 为全部候选建立 (question, hit["chunk"]["content"]) 的列表。
3. 调用 score_pairs 一次，把该列表传入，取得评分序列。
4. 检查评分数量与候选数量相同。
5. 按同一位置把候选和新评分关联起来，创建新结果字典。
6. 按新 score 稳定降序排序，截取 top_k。

输出每项：

```python
{
    "chunk": 原片段,
    "score": 新的模型评分,
    "retrieval_score": 原来的检索分数,
}
```

新旧分数都转换成 Python float，候选本身不修改。保留 retrieval_score 是为了在报告里看清“检索靠前，重排为何下降”，不把它与模型分数相加。

## 5. 需要的一点 Python 语法：zip

```python
names = ["A", "B", "C"]
scores = [0.2, 0.9, 0.4]

for name, score in zip(names, scores):
    print(name, score)
```

它按位置配对，依次得到 A/0.2、B/0.9、C/0.4。zip 默认以较短的一侧为准，因此先检查长度，避免静默遗漏候选。它不会按 ID 自动查找对应关系，候选顺序与评分顺序必须一致。

## 6. 两个常见实现错误

不要先做 candidates[:top_k] 再打分，那样原来第三名之后的正确片段没有机会进入最终结果。

不要让新评分与错误片段配对；评分函数返回的第一项就对应传入的第一对文本。模型评分成功、程序能运行，也不能代替检查该关联。
