# Day 6 第一课：两条检索路线与排名融合

## 1. 从已经发生的遗漏出发

问题：“我分别申请四天连续年假、周一和周二两天远程办公，各由谁审批？”

向量检索的前两名是“频率与审批”“固定现场日”，“年假审批”排第三。K=3 可以覆盖必要证据，但扩大最终 K 会增加上下文，也可能增加无关条款。今天固定最终 K=2，观察是否有其他策略能更好地选择片段。

这个失败发生在检索阶段，不靠重写生成 Prompt 修复。

## 2. BM25：按词项匹配排序

向量检索通过 Embedding 比较语义相近程度；BM25 主要利用问题与片段的词项匹配。BM25 结合词频、词项在语料中的稀有程度和文档长度：重复出现的收益会逐渐饱和，也会做长度归一化。它不是简单统计出现次数，也不依赖聊天模型。

它们常可互补，但不保证每个问题都有互补效果。词面不重合的同义表达可能影响关键词检索；向量检索也可能把同主题但不支持具体问题的条款排到前面。

中文文本先分词，本课由助教用 jieba.lcut_for_search 提供。文档和问题使用相同规则：casefold、搜索模式、HMM=False、保留 isalnum 词项。没有针对这道题手动写关键词或正确答案规则；实际分词未必理想，可在结果中检查。BM25Okapi 的 k1=1.5、b=0.75、epsilon=0.25 固定记录。

助教提供的 KeywordIndex 将当前同一数据库快照中的七个片段读入内存建立教学索引，不是大语料生产架构。没有词项重合的片段不加入该路候选。它不修改数据库，也不回退到旧文件索引。

原始真实报告已显示：本题 BM25 Top-2 为“频率与审批”“年假审批”，必要证据找齐；向量 Top-2 只找回一半。这是单题观察。

## 3. candidate_k 与 top_k 不同

```text
向量检索前 4 条 ─┐
                 ├→ 融合、去重、排序 → 最终前 2 条 → 后续构造上下文
BM25 检索前 4 条 ─┘
```

candidate_k=4 是每一路提供给融合器的最多候选数；top_k=2 是最终选出的最多片段数，两路共同的片段合并成一项。原生和框架问答中的 --top-k 仍是最终片段数；实验入口使用单独的 --candidate-k。本课先比较检索，不把融合自动接回问答。

如果相关片段没有进入任何一路候选，融合排序也无法凭空找回它。

## 4. 为什么不直接相加两路 score

本题向量第一名约 0.6351，BM25 第一名约 5.2750。前者是余弦相似度，后者是词项匹配分数；直接相加会引入分数尺度的影响。

RRF（Reciprocal Rank Fusion）只使用排名，等权版本对每个片段逐路累加：

```text
该路贡献 = 1 / (rank_constant + 本路排名)
融合分数 = 各路贡献之和
```

排名从 1 开始。某片段不在某路候选内，该路贡献为 0。rank_constant 本课固定 60，它是平滑排名差异的常数，与最终 K、候选数量都不同；60 不是对所有数据最优的结论。

简单例子：

| 排名 | 路线一 | 路线二 |
| --- | --- | --- |
| 1 | A | C |
| 2 | B | B |

A 得 1/61，C 得 1/61，B 得 1/62 + 1/62，所以 B 排第一。A、C 同分时按本课约定保留首次遇到的顺序，因此最后为 B、A、C。

融合分数不是余弦相似度，更不是“回答正确的概率”，不能继续套用余弦阈值。

## 5. 真实问题中，融合未必胜过单一路线

本题“固定现场日”与“年假审批”恰好在两路分别排 2/3 和 3/2：

```text
固定现场日 = 1/62 + 1/63
年假审批   = 1/63 + 1/62
```

两者同分。按首次遇到顺序，向量路的“固定现场日”在前，最终 K=2 时仍会挡住“年假审批”。这里即使改 rank_constant，两个对称的贡献之和仍相等。

因此函数实现正确和方案效果更好是两件事。保留这个现象，后续检查多题结果，再考虑关键词路线是否单独更适合、是否需要有依据地加权、查询拆分或重排。不要为了让这一题变好，立即改同分规则或把正确证据 ID 硬编码进去。

## 6. 唯一需要写的函数

文件 app/hybrid_retrieval.py，函数 fuse_rrf，输入输出和边界约定已经写在注释中。

建议按这五步实现：

1. 校验 top_k 和 rank_constant。
2. 建一个按 chunk ID 保存新命中字典的总字典。
3. 遍历每一路；本路用 seen 集合防止重复计分。
4. 遍历本路命中，按排名计算贡献，累加到对应片段的新 score 中。
5. 将总字典的值按融合分数稳定降序排序，截取 top_k 并返回。

复习会用到的 Python 语法：

```python
for rank, item in enumerate(items, start=1):
    ...  # rank 是名次，item 是该项

seen = set()
if identifier in seen:
    continue
seen.add(identifier)

# 与 Java Map 类似；新键按插入顺序保留。
totals = {}
totals["x"] = 0.0
totals["x"] += 0.5
values = list(totals.values())

# Python 排序是稳定的，同分保持原顺序。
ordered = sorted(values, reverse=True)
```

实际作业里的字典值是命中字典，需要按 item["score"] 排序，写法与你已有的 rank_chunks 相同。每次都创建新的命中字典，不直接修改原始 hit["score"]。同一 ID 跨路累加，本路 seen 则在每轮外层循环重新创建。
