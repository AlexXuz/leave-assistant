# Day4 · 最小RAG：切分、向量、排序与请求组装

目标：切分决定检索单位，Embedding把问题和文本映射成向量，排序只是在候选中找相关片段。相似度不是答案正确概率；证据没进TopK时改Prompt不能补回缺失材料。

## 先看完整数据流

```text
文档 → 带ID/版本的片段 → 离线文档向量 → 问题向量 → 排序 → TopK完整证据 → 消息。
```

## 关键概念与责任边界

prepare_corpus(documents, embedder)保留片段顺序、ID、原文与向量对应；retrieve_context(question, corpus, embedder, top_k)只编码问题并取已建索引，不在每次查询时重建全库。

代码职责分层：模型理解或生成建议；宿主注入身份/配置；确定性代码校验并执行；外部服务与数据库提供真实状态。当前单元只引入这一层需要的能力，不把后面的框架或生产系统提前堆进来。

Python中的dict/list是内存对象，JSON是文本；类型注解帮助IDE阅读结构，运行时约束需要Pydantic或明确检查。对已有Java经验，可以直接映射DTO、异常、事务与接口分层，但模型输出仍是不可信输入。

## 可以手算的向量：最小可核验案例

```text
问题向量：[1, 0]
片段a：[0, 1]，片段b：[1, 0]
归一化点积a=0、b=1；b应排前，分数与b的正文不能错配。
相似度1也不证明b能完整回答所有子问题。
```

官方/原始资料：[参考](https://www.sbert.net/docs/sentence_transformer/usage/semantic_textual_similarity.html)。

1. 从网页“独立任务”复制现成文件路径，在IDE看输入输出与类型；先运行热身观察未实现/已有状态。

3. 独立接通本课链路，再接页面/API或任务入口。暂不支持的情况明确失败。
4. 运行正常、变体、失败与恢复；逐条核对真实结果，再记录本人证据。

## 案例与失败定位

1. 一个问题同时需要两条制度，比较Top2与Top3证据覆盖。
2. 加入词面相似但规则不同的干扰片段，逐条核对ID和正文。

失败场景：构造向量行数/维度与片段不一致的索引，明确拒绝；重新构建一致索引后恢复，不能默默错配。

先定位发生在哪一层，再选修复动作。不能仅因网络失败换Prompt，不能以程序能跑就宣称语义正确，也不要求为了找模型错误刻意刁难。
