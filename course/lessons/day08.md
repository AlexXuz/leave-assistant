# Day8 · PDF与来源定位：从页面到可核验引用

目标：文本PDF解析要保留页码、文件指纹与字符位置，页内清理和切分不能丢失原文映射。引用只能映射本次授权命中，不能全库找一个看起来相关的ID。

## 先看完整数据流

```text
PDF文件/指纹 → 按页文本 → 保留定位的片段 → 授权检索 → sources校验 → 页码/范围引用。
```

## 关键概念与责任边界

ingest_document(path, profile, services)保留页面结构和定位；cite_authorized_sources(source_ids, hits)按回答顺序去重映射，仅允许本轮命中的ID。空文本/损坏/扫描件转明确失败或后续OCR流程。

代码职责分层：模型理解或生成建议；宿主注入身份/配置；确定性代码校验并执行；外部服务与数据库提供真实状态。当前单元只引入这一层需要的能力，不把后面的框架或生产系统提前堆进来。

Python中的dict/list是内存对象，JSON是文本；类型注解帮助IDE阅读结构，运行时约束需要Pydantic或明确检查。对已有Java经验，可以直接映射DTO、异常、事务与接口分层，但模型输出仍是不可信输入。

## 引用映射：最小可核验案例

```text
locator={kind: pdf, source_file: travel-policy.pdf, page: 2, start: 0, end: 92, source_sha256: ...}
回答要凭证时应引用第二页，不能只因第一页排名高就引用第一页。
数据库存在但本轮未授权命中的ID，仍不能用于引用。
```

官方/原始资料：[参考](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)。

## 动手顺序

1. 从网页“独立任务”复制现成文件路径，在IDE看输入输出与类型；先运行热身观察未实现/已有状态。
2. 用固定小样例手动跟踪调用链，明确每一步拿到什么对象，哪些来源可信。
3. 独立接通本课链路，再接页面/API或任务入口。暂不支持的情况明确失败。
4. 运行正常、变体、失败与恢复；逐条核对真实结果，再记录本人证据。

## 案例与失败定位

1. 住宿金额在第一页、凭证在第二页，引用必须覆盖实际所需页面。
2. 空白页、无文本页和损坏文件分别处理，不能伪造正文。

失败场景：中间页无法解析时停止整次入库，不发布部分快照；修复文件后重跑，旧已发布来源仍可读。

先定位发生在哪一层，再选修复动作。不能仅因网络失败换Prompt，不能以程序能跑就宣称语义正确，也不要求为了找模型错误刻意刁难。
