# Day9 · Word、表格与OCR：保留结构和质量边界

目标：Word应按段落和表格真实交错顺序读取，短章节保留表头、单位、数据和补充条件。Word没有稳定页码时用章节/块定位；OCR置信度不是语义正确率。

## 先看完整数据流

```text
DOCX正文块/表格 → 章节证据 → 文件版本/块范围 → 索引与引用；扫描页OCR → 字段/质量核验 → 接收或人工复核。
```

## 关键概念与责任边界

ingest_word(path, services)保持表格与条件同章并定位；route_ocr_review(lines, checks)综合置信度、关键字段、单位与条件，不让模型猜缺失金额。低质量来源不直接替换已发布知识。

代码职责分层：模型理解或生成建议；宿主注入身份/配置；确定性代码校验并执行；外部服务与数据库提供真实状态。当前单元只引入这一层需要的能力，不把后面的框架或生产系统提前堆进来。

Python中的dict/list是内存对象，JSON是文本；类型注解帮助IDE阅读结构，运行时约束需要Pydantic或明确检查。对已有Java经验，可以直接映射DTO、异常、事务与接口分层，但模型输出仍是不可信输入。

## 结构与单位：最小可核验案例

```text
先读住宿标准标题，再读表头“城市/上限/单位”、数据行和表后审批条件。
520元/每人每晚不能丢单位后当成一次出差总额。
OCR分数高也可能错关键金额、否定词或条件；质量审核要对照原图。
```

官方/原始资料：[参考](https://python-docx.readthedocs.io/en/latest/user/tables.html)。

## 动手顺序

1. 从网页“独立任务”复制现成文件路径，在IDE看输入输出与类型；先运行热身观察未实现/已有状态。
2. 用固定小样例手动跟踪调用链，明确每一步拿到什么对象，哪些来源可信。
3. 独立接通本课链路，再接页面/API或任务入口。暂不支持的情况明确失败。
4. 运行正常、变体、失败与恢复；逐条核对真实结果，再记录本人证据。

## 案例与失败定位

1. 变更其他城市住宿金额后，回答及引用跟随新版本，不混用旧表。
2. OCR总体分高但关键单位/否定词错误，仍要复核而不是自动接收。

失败场景：合并/嵌套表格等不支持结构明确失败；人工修订后的来源保留审计/原图，再重新入库，不覆盖原件。

先定位发生在哪一层，再选修复动作。不能仅因网络失败换Prompt，不能以程序能跑就宣称语义正确，也不要求为了找模型错误刻意刁难。

## 生产还差什么，以及下一步

小型OCR实验不等于工业审核队列、多页复杂表格或多模态检索。

下一步：需要复杂文档时按选修路线建立人工基准、审核与修订闭环，不只调整置信度阈值。
