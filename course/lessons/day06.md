# Day6 · 混合检索与重排：用证据评价优化

目标：BM25擅长词面信号，向量擅长语义近似；RRF按排名融合，不把不同路分数直接相加。重排只能处理已有候选，无法召回没进候选的证据。

## 先看完整数据流

```text
同一问题 → 向量候选/BM25候选 → 按ID去重融合 → 有限候选重排 → 最终K → 证据指标与逐题差异。
```

## 关键概念与责任边界

run_strategy_comparison(cases, retrievers, reranker)保留同一语料/参数/最终K；select_candidate(results, critical_cases)看逐题改进与退步，不只看平均分。用开发题选配置，再冻结后用新场景核对。

代码职责分层：模型理解或生成建议；宿主注入身份/配置；确定性代码校验并执行；外部服务与数据库提供真实状态。当前单元只引入这一层需要的能力，不把后面的框架或生产系统提前堆进来。

Python中的dict/list是内存对象，JSON是文本；类型注解帮助IDE阅读结构，运行时约束需要Pydantic或明确检查。对已有Java经验，可以直接映射DTO、异常、事务与接口分层，但模型输出仍是不可信输入。

## 排名融合：最小可核验案例

```text
向量路排名：a第一、b第二；词面路排名：b第一。
a贡献=1/(60+1)。
b贡献=1/(60+2)+1/(60+1)。
b融合后靠前，与两路原始分数的尺度无关。
```

官方/原始资料：[参考](https://cormack.uwaterloo.ca/cormack/rrf.pdf)。

## 案例与失败定位

1. 扩展同义改写和近邻干扰，不仅测词面直接匹配的题。
2. 一题需要两份证据，单份命中不能算全部召回。

失败场景：某方案平均分更高却丢失关键条款，应阻止采用；记录候选缺失和排序损失，再只改一个因素恢复对照。

先定位发生在哪一层，再选修复动作。不能仅因网络失败换Prompt，不能以程序能跑就宣称语义正确，也不要求为了找模型错误刻意刁难。
