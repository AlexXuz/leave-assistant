# Python大模型应用岗位的交付闭环

课程目标是独立交付Python大模型应用、迁移到新业务，而非保留Java技术栈或保证录用。已有后端经验可以迁移，作品集需有自己的Python/Agent实现。Day19/24/26是必交能力，专项按目标岗位选择。

## 1. 独立部署与恢复

复用已有隔离云主机或独立Linux测试环境，记录实际部署位置；本机Docker就如实写本机Docker，不冒称云生产。课程不会自动购买资源。

- 从指定commit/镜像启动本人Python服务、worker和持久存储，配置与密钥不进镜像/Git/前端。
- 测试入口有访问控制；公网需认证/TLS，数据库不公开，不能直接暴露教学密码和源码阅读页。
- 实际完成客服或新领域任务，保留任务ID、模型/工具调用和最终业务事实。
- 发布小变更再回滚；停止专用worker后恢复未完成任务，并验证一次外部副作用。
- 列出备份恢复、SSO、多实例哪些完成，哪些尚未执行。

交付环境/日期/预算、commit与镜像标识、脱敏日志、演示、重启和回滚记录。求职目标明确要求云时，再补真实云小闭环，不把不同环境混写。

## 2. Agent效果、安全与成本

按[安全评估](SECURITY_EVALUATION.md)验证用户、检索、工具和历史输入不能扩大权限。Day20用冻结场景进行真实模型重复运行，分别报告实际工具证据与人工任务判定；mode标签不证明模型实际执行。

逐trial保留成功/失败、复核覆盖率、模型/Prompt/工具版本、阶段与端到端耗时、实际usage及未知项。费用采用供应商有日期的计费口径或unknown；同任务同预算比较固定workflow/单Agent和一次单变量改动。关键违规阻止采用。

## 3. 跨领域与可解释故障演示

Day24从客服转到研发调查或资料研究，重新定义工具和完成条件。推荐故障是“外部测试工单已创建，但worker在保存检查点前退出”：展示远端动作ID、稳定幂等键、重启后的读回，证明没有重复创建。也可补充工具超时、旧人工决定、取消或证据冲突。

说明用户看到什么、哪层失败、哪些事实可信、如何恢复、如何验证和剩余限制。仅抛异常再从头跑不是进程恢复。

## 投递决策

Day25选择5–10个真实Python大模型应用/Agent岗位并聚焦一个主目标；核心要求以本人代码和实际运行支持，专项加分项可以列补缺计划。完成主线后可投递并用面试反馈迭代，不必补齐所有AI岗位。原后端经历与新的Python项目分别如实表达。
