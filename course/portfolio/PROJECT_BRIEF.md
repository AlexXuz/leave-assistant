# Python Agent 项目介绍模板

## 要解决的问题

填写客服调查或新领域任务：谁提出目标、为什么需要多个数据源、什么情况下应追问/停止、怎样判断任务真正完成。说明为什么选择模型决策循环或固定workflow。

## 我负责的部分

如实区分本人Python服务、模型适配、工具、状态与评测实现，以及参考代码/AI辅助/未完成内容。Java等后端经验是能力起点，项目交付栈为Python。

## 架构与关键取舍

画出API、模型、工具服务、检索、状态/检查点、事件和业务事实的数据流。说明异步/并发/deadline/取消、身份、人工决定、幂等和恢复边界。指出从客服迁移到新业务时重设计了哪些工具与成功标准。

## 验证与限制

填写真实模型/Prompt/工具版本、suite哈希、重复次数、人工复核覆盖率、任务成功与失败、成本未知项、p50/p95、部署/恢复记录。正确证据ID不等于语义正确。没有实测的规模、生产上线与业务收益保持未知。
