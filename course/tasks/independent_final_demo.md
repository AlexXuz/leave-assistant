# Day26 · 验收门三：Python Agent 应用综合交付

## 交付目标与起点

以本人完成的客服 Agent 和跨领域 Agent 为主，独立演示需求到产品、真实模型评测、部署、故障恢复与新需求修改。面向有后端经验、转向 Python 大模型应用的开发者，不要求 Java 集成。

本人演示与交付草稿写在 `course/projects/agent_product_delivery.md`，作者不替你填写；旧 `course/assignments/final_assessment.md` 保留为热身，不覆盖已有记录。既有 RAG、文档、ChatBI 和训练机制产物作为基础证据；不必把全部技术塞进同一用户流程，也不能以依次点击作者 OA 演示代替毕业项目。

## 输入输出与实现边界

交付可复现的源码 commit、依赖/配置说明、镜像或部署包、受控访问入口、评测原始记录、部署/恢复记录与个人演示。展示 Python 服务分层、异步 I/O、超时/取消、模型/工具适配、状态持久化与可信身份。

正常演示应从自己的入口接收目标，展示观察驱动决策、工具/检索事实、追问或停止、最终产物和业务读回。外部写动作只进入有权限与幂等保护的专用测试服务。说明真实模型、模拟依赖、人工审核分别承担什么验证。

部署在与日常开发进程分离的环境，可用已有隔离云主机。需实际完成启动、访问控制、一次版本发布/回滚及 worker 重启恢复。公网环境必须配置认证/TLS、密钥注入和数据库隔离；禁止直接暴露教学账号和源码阅读入口。课程不代购资源，不将未执行的云能力写成已完成。

## 公开变体练习

1. 新工具返回的字段或证据版本变化，更新适配、判定和回归，不能只修改 Prompt。
2. 不同模型或工具描述改变了调用路径，对同一冻结任务集重新比较效果、成本和失败；不强求新方案胜出。
3. 外部写入成功后 worker 退出，恢复并核对同一业务动作；另处理一个旧人工决定或取消中的任务。

上述题目已经公开，正式复核需确认新的需求未提前练过。按[证据规则](../EVIDENCE_PROTOCOL.md)保留基线、挑战与辅助使用记录。

## 失败、边界与恢复

由复核者在约定的隔离故障范围选择模型/工具超时、worker 退出、过期决策或证据冲突。用请求编号、任务 ID、工具结果和业务状态定位；演示恢复与回归，不能重置共享数据或换幂等键掩盖问题。

评测同时保留逐任务结果、多次运行波动、关键违规、延迟、用量和缺失 usage。命令 mode=live 只是声明，需实际调用记录佐证；模拟报告不能计入真实模型效果。自动检查通过后，语义与任务成功仍需人工复核。

## 验收标准

- **D26-C1**：独立演示本人 Python Agent 产品，从目标、观察驱动工具选择到可核验结果，并解释 Python 异步、超时与取消行为。
- **D26-C2**：展示客服与非 OA 新领域的迁移，现场完成一项真正未练过的需求变更，能指出复用和重设计的代码。
- **D26-C3**：身份、证据、人工决定、事务/幂等和恢复边界全部通过；任何越权、重复副作用、伪造成功或虚构证据均不通过。
- **D26-C4**：冻结任务集的真实模型重复运行、简单基线对照、逐任务评测、成本延迟和语义复核可追溯，明确样本与环境限制。
- **D26-C5**：独立部署、版本发布/回滚和实际 worker 故障恢复可复现，记录访问控制、日志、业务读回及未完成的生产能力。

五项不能以总分互相抵消；需通过 Day19、Day24 和 Day25 前置门。通过课程不等于所有 AI 岗位或生产经验认证。

## 操作与交付

1. 冻结演示版本，准备环境/预算、启动步骤、本人证据索引与已知缺口，领取 Day26 挑战。
2. 从自己的页面/API/命令入口运行正常、变体、失败恢复，分别保存 JSON 产物；演示视频与日志可以附引用，但必须能核对实际状态。
3. 填写 `course/submissions/independent_final_demo.json`，关联本人 commit、挑战、产物哈希和五项复核；不得复制作者报告或写未发生的 accepted。
4. 页面读取独立验收，或运行 `python -m scripts.check_course_assessment --day 26`。检查器验证记录结构与前置门，实际运行、语义、独立性和部署由复核者确认。
5. 将目标岗位的关键要求对应到本人证据；不能完成的专项列具体计划，不宣称“几乎所有岗位都已覆盖”。
