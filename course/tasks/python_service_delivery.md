# Day16 · 独立交付：Python 服务结构、生命周期与容器启动

## 交付目标与起点

把模型/工具调用做成自己的 Python HTTP 服务。它可以先服务客服工单查询，也可以暂接已验收的业务接口；核心是自己完成模块边界、配置、类型、资源管理与启动，而非只运行作者办公助手。

在 IDE 打开 `course/projects/python_service_runtime.py`。新增文件提供契约与待实现函数，原 `course/assignments/deployment_verification.md` 保留作为操作记录参考。已有 Day1–Day11代码和数据库不得重置。

按三个小阶段交付：A. 离线导入与配置/API契约；B. 生命周期与真实依赖；C. 本人镜像启动和恢复。单元可跨多个学习时段，不要求一天塞完。

## 输入输出与实现边界

- `load_settings(environment)` 从显式环境映射建立 `ServiceSettings`；拒绝缺失/空配置、非法超时和并发上限。日志只标配置名，不输出凭证。
- `create_app(settings, resource_factory)` 返回本人的 FastAPI 应用。资源工厂是异步上下文管理器，交付一个业务处理端口和有时限的就绪探测端口；创建应用本身不联网。
- 学员自行实现 Pydantic 请求/响应模型、真实适配器、可信身份依赖与启动入口。至少一条业务 API 必须区分校验失败、外部依赖失败和业务结果，不用宽泛的 `except Exception: return ok`。
- 提供 `/health/live` 和 `/health/ready`：后者探测必要依赖、超时返回未就绪，不能只检查环境变量存在。健康检查不触发付费模型生成。
- 资源在 lifespan 中建立/关闭。测试可注入替身；真实客户端不能为每个请求重新创建，也不能在模块导入时连接外网。同步 I/O 的异步隔离在 Day17完成。

允许自行扩充类型和拆分模块。Protocol只描述接口，不替代校验或授权。将身份绑定在服务端适配层，不能让模型或请求body指定可信身份。

## 公开变体练习

1. 从“只有模型接口”变成“模型与一个只读 HTTP 工具”，分别配置连接期限；工具不可用时准确报告依赖问题。
2. 启动时第二个资源初始化失败，已经建立的第一个资源仍须关闭；纠正配置后能再次启动。

以上是公开练习，不冒称未见题。按[证据规则](../EVIDENCE_PROTOCOL.md)冻结基线后领取挑战；看过相同要求应说明，再由复核者提供新条件。

## 失败、边界与恢复

在隔离服务中分别使用缺失配置和不可达工具端口。观察启动拒绝或未就绪状态，修复依赖后恢复；重启本人镜像，读回同一持久业务记录。使用独立项目/卷，不通过清空数据库掩盖失败。关闭测试客户端或应用后，验证资源关闭计数/连接状态，不能只看日志写了“closed”。

## 验收标准

- **D16-C1**：本人模块可离线导入，配置与 Pydantic 边界生效，API调用的是本人服务适配层；能解释依赖方向。
- **D16-C2**：lifespan负责资源创建与释放，正常退出及部分启动失败均有关闭证据；替身与真实依赖清楚区分。
- **D16-C3**：从锁定依赖构建并运行本人容器，存活/就绪结果准确，实际业务 API 和至少一次真实模型调用可追溯，重启后持久状态仍可读回。
- **D16-C4**：缺配置/依赖失效可定位并恢复，镜像、响应、日志不泄露密钥；保留环境、镜像标识和命令记录。

任何关键项未过不记整课完成；作者镜像通过不代替本人证据。模型网络受限时如实记录未执行，离线契约通过不能替代真实调用要求。

## 操作与交付

保存设计与基线 commit，运行自己的入口，分别留正常、公开变体、失败恢复产物。记录 Python/依赖版本、入口模块、镜像摘要、回环端口、数据卷、请求编号、依赖类型和限制。真实模型记录 `model_called=true` 与模型/usage；替身标 false。
