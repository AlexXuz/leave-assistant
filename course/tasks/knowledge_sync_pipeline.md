# Day7 · 知识生命周期与权限：快照、事务和授权检索

## 交付目标与起点

完整快照才能推断删除；规划和执行分离。元数据变化、正文变化与不变要区分，写库时复查来源版本，旧批次不能覆盖新批次。授权必须先于TopK和模型。

热身文件 `app/document_sync.py`；独立任务文件 `course/projects/knowledge_sync_pipeline.py` 已创建。主线main从待实现骨架起步；作者示范有单独入口。alexstudy保留个人历史实现，不作为新学员默认进度。

## 输入输出与实现边界

synchronize_source(snapshot, store, embedder)规划后再事务应用，失败回滚；prepare_visible_request(question, trusted_access, store, top_k)从服务端身份派生来源/部门范围，过滤后再排名。

数据流：同来源完整快照 → 同步计划 → 事务/版本复查 → 更新片段与清单 → 权限SQL过滤 → TopK → 授权消息。

可在[独立工作区](../projects/README.md)接自己的页面/API，先用固定依赖替身理解，再按环境说明运行真实依赖。业务阶段不同，不能为了演示提前增加写权限或猜数据。

## 公开变体练习

1. 只改标题/定位与改正文分别走不同更新策略。
2. 无部门权限时只见明确公开材料，不能用过滤后的TopK缺口作为放宽权限理由。

这些已经公开，不当作秘密留出题。冻结自己的基线，再领取变体；若已读或练过，请复核者换一条新的业务要求。

## 失败与恢复

事务中途失败后读不到半成品；旧批次遇到更新后的来源必须冲突。重新规划同快照可以成功，不重复编码不变正文。

算法/校验题通过修正数据并重新运行恢复，不强造进程崩溃。依赖错误和业务拒绝要保留具体观察。

## 验收标准

- **D7-C1**：完整快照、来源隔离、版本检查与原子回滚有证据。
- **D7-C2**：检索前权限过滤，未知身份不扩大范围。
- **D7-C3**：授权命中才进入模型，过期/删除文档不残留。

保存自己的正常、变体、失败与恢复记录；填写 `course/submissions/knowledge_sync_pipeline.json`。热身通过不等于整课完成，复核与哈希规则见[证据协议](../EVIDENCE_PROTOCOL.md)。CLI只用于辅助，主要交付应能从自己的页面、API或明确入口复现。
