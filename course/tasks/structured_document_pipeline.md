# Day9 · Word、表格与OCR：保留结构和质量边界

## 交付目标与起点

Word应按段落和表格真实交错顺序读取，短章节保留表头、单位、数据和补充条件。Word没有稳定页码时用章节/块定位；OCR置信度不是语义正确率。

热身文件 `app/docx_ingestion.py`；独立任务文件 `course/projects/structured_document_pipeline.py` 已创建。主线main从待实现骨架起步；作者示范有单独入口。alexstudy保留个人历史实现，不作为新学员默认进度。

## 输入输出与实现边界

ingest_word(path, services)保持表格与条件同章并定位；route_ocr_review(lines, checks)综合置信度、关键字段、单位与条件，不让模型猜缺失金额。低质量来源不直接替换已发布知识。

数据流：DOCX正文块/表格 → 章节证据 → 文件版本/块范围 → 索引与引用；扫描页OCR → 字段/质量核验 → 接收或人工复核。

可在[独立工作区](../projects/README.md)接自己的页面/API，先用固定依赖替身理解，再按环境说明运行真实依赖。业务阶段不同，不能为了演示提前增加写权限或猜数据。

## 公开变体练习

1. 变更其他城市住宿金额后，回答及引用跟随新版本，不混用旧表。
2. OCR总体分高但关键单位/否定词错误，仍要复核而不是自动接收。

这些已经公开，不当作秘密留出题。冻结自己的基线，再领取变体；若已读或练过，请复核者换一条新的业务要求。

## 失败与恢复

合并/嵌套表格等不支持结构明确失败；人工修订后的来源保留审计/原图，再重新入库，不覆盖原件。

算法/校验题通过修正数据并重新运行恢复，不强造进程崩溃。依赖错误和业务拒绝要保留具体观察。

## 验收标准

- **D9-C1**：段落/表格顺序、单位、条件与章节定位完整。
- **D9-C2**：Word不伪造页码，版本变更可追溯。
- **D9-C3**：OCR质量差与可靠缺失分开，关键字段不猜测。

保存自己的正常、变体、失败与恢复记录；填写 `course/submissions/structured_document_pipeline.json`。热身通过不等于整课完成，复核与哈希规则见[证据协议](../EVIDENCE_PROTOCOL.md)。CLI只用于辅助，主要交付应能从自己的页面、API或明确入口复现。
