# Day17 · 独立交付：有预算的异步工具执行与事件流

## 交付目标与起点

在 Day16 的本人 Python 服务中实现异步执行层：限定工具并发、覆盖排队和调用的总期限、显式取消、持久 SSE 事件及断线重连。Day19复用它实现模型决策循环，本课不代写决策逻辑。

入口 `course/projects/async_tool_runtime.py` 是未实现契约。原 `course/assignments/sse_events.py` 与 `course/projects/resumable_report_stream.py` 保留作热身，不用覆盖原答案。

## 输入输出与实现边界

- `execute_tool_batch(calls, invoke, limits, cancel_requested)` 执行已由宿主授权、相互独立的一批只读调用；保留 tool_call_id，将允许的工具失败转为结构化结果，结果按输入顺序返回。校验重复ID、空/非法限制和不支持的工具。
- 总期限从进入执行器开始，包含排队、单次调用与重试；剩余时长传到异步调用适配器。真实模型与工具客户端必须异步，不能在async函数里直接阻塞线程。
- 外部取消应在资源清理后传播 `CancelledError`；用户显式取消可返回 `cancelled` 状态，但不再启动新工具。终态要准确区分 `ok/error/timeout/cancelled`，不把未执行工具写为成功。
- `stream_job_events(job_id, after_id, principal, events)` 返回异步 SSE 帧迭代器。principal必须来自宿主会话；先验证归属，读取持久序号，遵循 after/Last-Event-ID，不丢最后终态。按事件ID去重，说明断线继续、显式取消停止的约定。
- 工具层只提交结构化结果；进入模型 messages 时由 Day19维护 assistant/tool_call_id 配对。本课先记录真实 `tool_started/tool_finished/error/cancelled` 等事件。

API/事件存储适配器和异步模型入口由本人实现。事件和终态持久化不等于worker可跨进程恢复；进程死亡后续跑留到Day24。

## 公开变体练习

1. 将并发上限从2改成1，慢工具占满槽位时后续请求仍受同一总期限约束，不能等到执行才开始计时。
2. 工具完成时SSE恰好断线；使用最后收到的ID重连，既不漏掉终态，也不重复执行业务。

公开条件不是秘密留出集，按[证据规则](../EVIDENCE_PROTOCOL.md)冻结基线并由复核者确认新要求。不要仅换延迟数字充当需求迁移。

## 失败、边界与恢复

先用 Event/屏障控制慢工具已启动，注入超时、工具业务失败和用户取消，记录在途计数峰值、后续工具是否启动、连接关闭和终态次数。再起独立本机 HTTP 工具服务，实际发请求、断开订阅和重连；内存替身不能冒充HTTP链路。

另接一次真实异步模型调用，若接口支持流式则展示实际模型增量，不支持时明确只有阶段事件。替身可稳定测试取消/异常，不能证明实际供应商取消了服务端生成或未计费。取消结果不确定的远端副作用应记 outcome_unknown，不能宣称撤销。

## 验收标准

- **D17-C1**：本人异步模型/工具 I/O 可运行，有界并发实测不超限，总期限覆盖排队与调用；禁止阻塞事件循环的接线。
- **D17-C2**：超时、工具业务错误和取消可区分，停止新调用并释放可取消资源，取消不会伪造成功或撤销远端副作用。
- **D17-C3**：持久事件按任务递增，订阅校验归属，Last-Event-ID/after重连不漏终态；客户端去重不导致重执行业务。
- **D17-C4**：有可重复的慢工具/并发/取消测试、本机HTTP演示和真实模型记录；三类数据来源明确，流式能力与未实现恢复边界说明准确。
