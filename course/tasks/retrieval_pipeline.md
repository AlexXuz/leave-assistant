# Day4 · 最小RAG：切分、向量、排序与请求组装

## 交付目标与起点

切分决定检索单位，Embedding把问题和文本映射成向量，排序只是在候选中找相关片段。相似度不是答案正确概率；证据没进TopK时改Prompt不能补回缺失材料。

热身文件 `app/retrieval.py`；独立任务文件 `course/projects/retrieval_pipeline.py` 已创建。主线main从待实现骨架起步；作者示范有单独入口。alexstudy保留个人历史实现，不作为新学员默认进度。

## 输入输出与实现边界

prepare_corpus(documents, embedder)保留片段顺序、ID、原文与向量对应；retrieve_context(question, corpus, embedder, top_k)只编码问题并取已建索引，不在每次查询时重建全库。

数据流：文档 → 带ID/版本的片段 → 离线文档向量 → 问题向量 → 排序 → TopK完整证据 → 消息。

可在[独立工作区](../projects/README.md)接自己的页面/API，先用固定依赖替身理解，再按环境说明运行真实依赖。业务阶段不同，不能为了演示提前增加写权限或猜数据。

## 公开变体练习

1. 一个问题同时需要两条制度，比较Top2与Top3证据覆盖。
2. 加入词面相似但规则不同的干扰片段，逐条核对ID和正文。

这些已经公开，不当作秘密留出题。冻结自己的基线，再领取变体；若已读或练过，请复核者换一条新的业务要求。

## 失败与恢复

构造向量行数/维度与片段不一致的索引，明确拒绝；重新构建一致索引后恢复，不能默默错配。

算法/校验题通过修正数据并重新运行恢复，不强造进程崩溃。依赖错误和业务拒绝要保留具体观察。

## 验收标准

- **D4-C1**：排序分数与片段一一对应，原文/元数据完整。
- **D4-C2**：查询只编码问题，索引与模型配置可追溯。
- **D4-C3**：区分候选缺失、排序问题和生成错误，检查输入不被修改。
