# Day13 · 独立接线：跨轮修改、压缩和偏好删除

## 交付目标与起点

构造一条读取当前业务快照、选择历史、注入偏好、形成模型请求的完整链路。让同一账号先说四天再改两天，处理完后回答当前状态，不能仅对一份静态字典做裁剪。

直接在IDE打开 `course/projects/conversation_context_pipeline.py`；已经创建，保留原 `course/assignments/context_selection.py` 作为热身。基础设施/运行示范可以阅读，但必须说明引用范围，不能以调用示范入口作为独立实现。

页面/API脚手架与带类型的服务端口见[独立工作区](../projects/README.md)。可用8014独立入口登录四个演示账号接线，不消耗8012主页面额度。

## 输入输出与实现边界

prepare_request(question, turns, services, budget_chars)返回messages、budget和evidence_sources；services暴露read_snapshot()与read_preference()，每次请求重新读取，不能从历史反序列化身份。delete_preference(services)执行删除并返回后续请求不再注入的可观测结果。保留成组tool_call/tool结果或明确拒绝不支持的消息组。

新增适配器和界面可放在本课项目目录或自己的分支。不要修改已验收Day1–Day11；通过接口、包装或组合复用。接口、类型与错误结构由你设计并在报告说明，脚手架不是逐行答案。

## 公开变体练习

1. 支持一个完整assistant tool_calls与两个tool结果组成的不可拆分历史组。
2. 业务状态已提交，但旧摘要仍写待确认；构造上下文时必须说明以最新快照为准。

以上已经公开，不冒称保密留出题。先冻结基线再领取一轮挑战；挑战抽签也来自公开任务族。若已读或练过该条件，向评审说明并换一条新业务要求。真正“未见”需由复核者确认，不由随机参数或脚本自动认证。

## 失败、边界与恢复

模拟偏好读取超时与必要业务快照读取失败，分别选择明确降级或停止；不可悄悄沿用旧余额。删除后重建服务，偏好仍不能重新出现。

正常、公开变体、失败恢复各保存一次独立运行：输入、环境、预期、实际、请求/业务编号和限制。纯数据处理题的恢复是纠正输入/数据并重跑，不强造事务或进程崩溃。

## 验收标准

- **D13-C1**：当前问题与最新快照保留；输入不被修改，完整消息组不拆散。
- **D13-C2**：不同账号隔离，偏好删除后下次请求及重启后不注入。
- **D13-C3**：快照失败不猜余额；预算不足有明确错误，不伪造精确token统计。

这些是不可用总分抵消的关键项。热身自动检查只验证函数契约，本任务还需真实运行证据与复核。

## 操作与交付

1. 在网页“独立任务”查看要求，或IDE打开上方项目文件。先写方案与输入输出，再实现接线。
2. 保存基线commit；网页领取本轮挑战，或运行 `python -m scripts.issue_course_challenge --day 13`。在查看完整示范之前记录尝试和所用提示。
3. 实现后从自己的页面/API/脚本实际运行，编写必要的接口/集成检查。保存正常、变体、失败与恢复的JSON运行记录，不能复制作者报告。
4. 填写 `course/submissions/conversation_context_pipeline.json`，使用 `course/EVIDENCE_PROTOCOL.md` 的格式；记录源码commit、挑战编号和产物SHA256。文件模板已经创建，默认全部待完成。
5. 网页点“读取独立验收”，或运行 `python -m scripts.check_course_assessment --day 13`。脚本核验结构、文件与哈希；语义、独立性与新需求仍须复核。不得为变绿而填写没有发生的accepted。
