# Day2 · Pydantic与评测：建立可执行的数据契约

## 交付目标与起点

模型说是JSON，不代表字段正确。Pydantic负责类型/额外字段/日期，服务端负责日期关系、支持范围与missingFields。格式、业务和语义结果分开评估。

热身文件 `app/exercises.py`；独立任务文件 `course/projects/validated_output_pipeline.py` 已创建。主线main从待实现骨架起步；作者示范有单独入口。alexstudy保留个人历史实现，不作为新学员默认进度。

## 输入输出与实现边界

validate_extraction(payload, reference_time)返回严格校验的四字段与missingFields；map_validation_error(error)区分JSON、Schema、日期关系。自己定义DTO，避免把模型给出的missingFields直接当事实。

数据流：助手字符串 → JSON解析 → Schema校验 → 日期/字段关系 → 服务端缺失字段 → 逐案例评测。

可在[独立工作区](../projects/README.md)接自己的页面/API，先用固定依赖替身理解，再按环境说明运行真实依赖。业务阶段不同，不能为了演示提前增加写权限或猜数据。

## 公开变体练习

1. 空白理由归一为空，非法日期与日期倒置分别拒绝。
2. 模型声称missingFields=[]，但结束日期缺失，服务端必须修正而不是放行。

这些已经公开，不当作秘密留出题。冻结自己的基线，再领取变体；若已读或练过，请复核者换一条新的业务要求。

## 验收标准

- **D2-C1**：额外字段与非法日期拒绝，缺失字段由服务端计算。
- **D2-C2**：无记录/空值与真实0等不同语义不混淆。
- **D2-C3**：逐例期望/实际与失败层可复现，不把网络失败计成语义答错。
