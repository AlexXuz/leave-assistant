# Day24 · 验收门二：跨领域 Agent 与可恢复执行

## 交付目标与起点

离开客服与 OA，选择研发故障调查或资料研究，独立设计并实现一个 Python Agent 服务。新领域必须有不同的数据源、工具、证据与完成条件，不能只换实体名称。加入持久化任务、人工决策和隔离外部服务的一次幂等副作用。

入口 `course/projects/cross_domain_agent.py` 只提供待实现的启动/恢复/读状态函数。可复用自己已验收的模型与工具基础设施；旧 `department_policy_integration.py` 和部门上限练习保留，但不再充当本门主项目。

## 输入输出与实现边界

自行定义任务 DTO、状态机、领域工具 Schema、成功判据和评测适配器。`start_task(request, services)` 接收目标与业务输入，身份由宿主绑定的 services 提供；`resume_task(task_id, decision, services)` 校验任务归属、版本与人工决定；`read_task` 只返回当前账号有权访问的状态和证据。

推荐两条路线：研发调查读取脱敏日志/近期发布/手册后创建测试工单；资料研究检索多个版本的来源，核对冲突后保存测试报告。外部写动作只能发生在专用测试服务中；不能修改真实生产配置、发送真实客户消息或将模型推断直接写为已验证事实。

至少写清两项领域变化，例如时间窗口和部署版本影响日志证据，或来源日期与互相引用影响研究结论。复用通用框架不等于复用旧领域的工具/判定器；成功与失败案例需为新领域重新设计。

持久存储任务目标、完整消息组、证据引用、待决策动作、版本、事件游标和终态。业务服务保留事实与幂等记录；检查点仅保存执行位置。设计并验证外部动作已完成而本地检查点未更新的窗口；结果不确定时查询远端或转人工，禁止盲目换 key 重试。两个 worker 竞争恢复时需要明确锁/租约/版本方案及限制。

## 公开变体练习

1. 研发调查中发现手册属于旧版本，当前发布信息更新；研究路线中两份来源日期不同且结论冲突。Agent必须继续核对或明确无法确认。
2. 人工确认后任务目标或证据版本改变，旧决定不能无条件沿用。
3. 外部测试服务已记录动作，worker 在保存观察前退出；恢复后只读回或幂等复用同一动作。

以上是公开任务族，不冒称秘密题。冻结基线后由复核者提出真正未练过的领域要求，说明区别与来源；遵守[证据规则](../EVIDENCE_PROTOCOL.md)。

## 失败、边界与恢复

在隔离 worker 进程验证：工具返回前退出、外部写入后检查点前退出、旧人工决定、两个 worker 同时恢复。保留实际进程退出与重建记录、同一任务 ID、外部动作 ID、恢复前后业务数量和事件序号。函数内抛异常再从头运行不等于进程恢复。

用户取消后不再发起新动作；已经发送的外部调用是否可撤销，以工具契约和读回事实为准。禁止用清库或新增幂等键隐藏重复动作。模拟依赖可用于可控故障，至少另有真实模型决策与独立进程工具联调，分别标识。

## 验收标准

- **D24-C1**：交付非客服、非 OA 的独立 Agent；新数据源、工具、成功标准与至少两项领域变化有设计和实际运行证据。
- **D24-C2**：模型依据新领域观察调整行动，证据冲突、缺失或过期有正确处理；新领域任务集经过真实模型运行与人工核验。
- **D24-C3**：任务持久化后能从实际 worker 退出中恢复；覆盖外部已写、检查点未存窗口，读回证明同一动作只发生一次。
- **D24-C4**：任务归属、版本绑定人工决策、取消与并发恢复有后端约束；过期决定或竞争不能产生未授权或重复动作。
- **D24-C5**：从自己的服务完成正常、新需求、失败恢复；代码、运行报告、业务事实和复现步骤一致，能解释复用与重设计的边界。

五项均须通过，并满足 Day19 及课程前置验收。关键违规不能被总体分数抵消。

## 操作与交付

1. 冻结原客服基线，提交新领域需求、工具/证据契约、完成条件、故障窗口和设计取舍；领取 Day24 挑战。
2. 在自己的 Python 服务实现并部署独立 worker、持久状态及测试外部接口，先做确定性恢复回归，再做真实模型任务运行。
3. 正常、公开变体和失败恢复分别保存本人产物；外部业务读回、worker 重建及并发证据不能只用模型文字说明。
4. 填写 `course/submissions/cross_domain_agent_delivery.json`，关联本人 commit、挑战和哈希。页面读取独立验收或运行 `python -m scripts.check_course_assessment --day 24`。
5. 由复核者重跑关键窗口并提出新要求，填写五项复核结论；不得仅为让页面变绿而申报 accepted。

## 分级提示

[分级提示](../solutions/cross_domain_agent_delivery.md)只提供拆解与排查方法。先自己定义事实和状态，再选择持久化或编排工具；不要求用某一种框架复制现成应用。

## 生产边界与下一步

本任务证明限定负载、隔离外部服务下的迁移与恢复能力，不等于生产 HA、真实根因定位准确率或任意网站研究能力。Day26在独立部署环境复验发布、回滚、监控与故障处理；没有执行的生产能力如实列缺口。
