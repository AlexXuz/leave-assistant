# Day6 · 混合检索与重排：用证据评价优化

## 交付目标与起点

BM25擅长词面信号，向量擅长语义近似；RRF按排名融合，不把不同路分数直接相加。重排只能处理已有候选，无法召回没进候选的证据。

热身文件 `app/hybrid_retrieval.py`；独立任务文件 `course/projects/retrieval_experiment.py` 已创建。主线main从待实现骨架起步；作者示范有单独入口。alexstudy保留个人历史实现，不作为新学员默认进度。

## 输入输出与实现边界

run_strategy_comparison(cases, retrievers, reranker)保留同一语料/参数/最终K；select_candidate(results, critical_cases)看逐题改进与退步，不只看平均分。用开发题选配置，再冻结后用新场景核对。

数据流：同一问题 → 向量候选/BM25候选 → 按ID去重融合 → 有限候选重排 → 最终K → 证据指标与逐题差异。

可在[独立工作区](../projects/README.md)接自己的页面/API，先用固定依赖替身理解，再按环境说明运行真实依赖。业务阶段不同，不能为了演示提前增加写权限或猜数据。

## 公开变体练习

1. 扩展同义改写和近邻干扰，不仅测词面直接匹配的题。
2. 一题需要两份证据，单份命中不能算全部召回。

这些已经公开，不当作秘密留出题。冻结自己的基线，再领取变体；若已读或练过，请复核者换一条新的业务要求。

## 失败与恢复

某方案平均分更高却丢失关键条款，应阻止采用；记录候选缺失和排序损失，再只改一个因素恢复对照。

算法/校验题通过修正数据并重新运行恢复，不强造进程崩溃。依赖错误和业务拒绝要保留具体观察。

## 验收标准

- **D6-C1**：融合按ID和本路排名去重，重排分数不冒充原检索分数。
- **D6-C2**：候选K/最终K、语料/模型与场景划分有记录。
- **D6-C3**：保留退步案例与基线，不把检索指标写成回答准确率。

保存自己的正常、变体、失败与恢复记录；填写 `course/submissions/retrieval_experiment.json`。热身通过不等于整课完成，复核与哈希规则见[证据协议](../EVIDENCE_PROTOCOL.md)。CLI只用于辅助，主要交付应能从自己的页面、API或明确入口复现。
