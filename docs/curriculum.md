## 新增模块的学习边界与作业

### 真实文档导入（D8–D9）

沿用当前知识库，不另起一个 RAG 项目。接入少量文本型 PDF、DOCX 和带表格的制度样本；补一个单页扫描件 OCR 实验，理解识别结果可能出错。网页抽取作为同类适配练习，时间不足时选做。解析输出统一为正文与来源元数据，再复用现有切分、向量化和同步流程。

核心作业：替换一份 Markdown 制度为 PDF/Word 来源，保留稳定文档 ID、版本和页码/章节位置。对照原文验证正文与表格没有错序、遗漏或错误合并；解析失败不能当作空快照触发删除。回答应能追溯到具体位置，无法可靠提取的内容记录限制，不编造缺失字段。

不要求这两单元掌握复杂布局、多页合并表格、公式识别和工业级 OCR。pgvector 精确检索与近似索引保留为受控实验，结合数据规模安排，不为增加数据库产品名称重复搭建。

### 上下文工程与记忆（D12–D13）

先区分业务事实、对话消息、检索证据、工具返回和长期偏好。学习 Token 预算、消息选择、工具结果裁剪、历史压缩和结构化状态；理解缓存、检查点与长期记忆分别解决什么问题。用户身份、授权和已提交业务结果不能仅保存在模型生成的摘要里。

核心作业：在多轮修改假种、日期和理由后压缩历史，仍能正确生成最新草稿，并在恢复流程时保持确认状态。增加一项可查看、修改、删除且按用户隔离的长期偏好；验证删除后下次请求不再带入。用已有用量日志比较压缩前后上下文大小，不要求搭建复杂记忆平台。

### MCP 集成（D14）

复用已有业务函数，不另写重复业务逻辑。学习 host/client/server、工具发现和 Schema、工具调用与结果、stdio 和 Streamable HTTP 的用途及身份传递；理解模型 Tool Calling 与 MCP 协议处在不同层次。以实施时官方规范和 SDK 支持的版本为准，不死记握手细节。

核心作业：将一项只读业务查询暴露为 MCP 工具，分别通过自建 Agent 与独立客户端调用。能解释模型如何选择工具、应用如何路由、服务端如何校验身份和返回结果；验证无权限和工具异常。写操作继续沿用原有确认、权限与幂等边界，接入 MCP 不授予额外业务权限。

### Skills 封装（D15）

学习 SKILL.md 的元数据与任务说明、scripts/references/assets 的组织、按需加载和执行结果验证。先做可解释的最小发现和加载逻辑，理解宿主如何执行技能；不把复制一个目录当作已经实现完整技能运行系统。Skill 描述完成任务的方法，MCP 连接可调用的能力，LangGraph 管理状态和执行流程。

核心作业：制作“部门请假统计报告”Skill，包含说明、输出模板与一个调用既有业务接口的脚本。演示一次从任务匹配、读取说明到生成报告的完整过程，保留加载轨迹；输入或资料中的指令不能扩大权限。当前只执行已审核脚本，不将普通子进程或 Docker 容器直接称为可安全执行任意代码的沙箱。该 Skill 先用既有统计接口，不依赖尚未学习的 Text2SQL。

### 小型 ChatBI（D22–D23）

在模拟部门、员工、请假记录等少量表上练习，形成“本月各部门请假天数与上月比较”的可演示功能。学习 Schema 描述、自然语言生成 SQL、查询校验、数据库执行、结果解释与图表；区分查制度文本与查实时业务数据。框架只承担编排，学习者应能追踪实际 SQL、参数、结果和解释之间的关系。

核心作业：先手写参考 SQL，再对照模型生成 SQL、实际查询结果和图表数值；加入一个歧义问题和一个无权查询的问题。数据库使用只读角色，在数据库或受控查询层落实用户数据范围，并设置语句超时与结果行数限制；不能只依赖 Prompt、SELECT 前缀或正则判断。无需支持任意数据库、任意 SQL 或完整仪表盘。

## 选修边界

- 多 Agent：先能解释单 Agent 与确定性流程的取舍，再做一次两角色协作对照；深入调度、共享状态和并行成本单独安排。
- 浏览器自动化与代码执行沙箱：面向办公自动化岗位再增加，分别验证执行权限、环境隔离和失败恢复，不混入当前主项目的任意执行能力。
- 多模态：图文检索、CLIP、图片/视频理解作为独立方向；PDF 文本解析或 OCR 不等于已掌握多模态检索。
- 专项文档：复杂 OCR、版面理解、公式识别与符号计算按目标岗位选择，不为覆盖培训项目名强行加入主线。
- 产品与框架迁移：可选一个其他 Agent 产品或框架迁移已完成的能力，考察接口与架构差异，不要求逐个搭建同类框架和向量库。

选修不计入上述 26 单元；需要深入学习时另外估算时间。24 单元原计划不是加入全部新内容后仍不变的工期承诺。

## 贯穿每个阶段的验收

1. **直接调用**：从第一次调用记录模型、Prompt 版本、耗时、结束原因和接口提供的 Token 用量。确定性测试使用模拟响应；真实模型评测单独执行。
2. **结构化输出**：Day 2 起验证字段类型、枚举、日期和一致性。missingFields 由服务端按必填规则计算或核验，模型声明不作为业务事实。
3. **RAG**：先建 30–50 条教学评测，标注答案要点、证据来源、是否应拒答；划分调试集与保留集。分别看证据检索、回答依据、引用正确性和拒答，不只报告一个准确率。
4. **RAG 数据链路**：包括原始文档/版本/片段关联、更新和删除。引入部门权限时就验证无权限内容不会进入模型上下文；检索内容中的指令不授予工具权限。
5. **业务工具**：第一项写操作就验证真实用户身份、权限、确认与幂等。以数据库或模拟业务服务的最终状态验收，不以模型说“已成功”验收。
6. **Agent**：先实现明确流程，再增加模型选择步骤的能力。验证最大步骤、总超时/用量预算、工具失败、重复执行和暂停后的恢复。
7. **独立掌握**：每阶段都要能讲清调用链、定位一处失败、完成一个未见需求变化。对答案质量敏感的案例适当重复试验，保留波动。
8. **上下文与记忆**：能展示最终发给模型的内容及取舍；压缩不覆盖最新业务状态，长期记忆按用户隔离并可更新、删除。
9. **MCP 与 Skills**：以独立客户端调用和实际技能加载/执行记录验收，不以写了配置文件或目录结构验收。
10. **ChatBI**：查询结果与参考 SQL 一致，图表数值可追溯；数据库权限和资源限制独立于模型声明，歧义或权限不足时不强行回答。

教学小样本用于发现问题、比较方案，不用于宣称生产可靠性。性能报告必须记录模型、输入规模、并发、样本量及是否真实调用。

## RAG 的优化顺序

先检查文档是否正确解析、相关证据是否入库、检索能否找到；再检查上下文拼装和生成。
基线建立后，每次只改变一项：切分、检索参数、关键词混合检索、重排、查询改写等，并用同一评测集比较。
pgvector 的精确检索和近似索引作为一个对照实验；不要求为了覆盖知识点同时搭建多种向量数据库。

## 学习与 AI 辅助

- 首日用 20–30 分钟诊断 Python 基础；已经掌握的内容直接跳过，其他语法随代码补充。
- 每个新核心链路先亲手实现最小版本，再用 AI 审查与框架重构。业务样板、页面和部署脚手架可以让 AI 辅助生成。
- 每个任务给出输入输出契约、原理、最小示例、练习和验收。逐步撤掉函数填空，后续模块由学习者独立拆解。
- 卡住时可以请求提示、解释或排查方向。能够复述、修改并验证实现，是是否掌握的依据。
- 每天采用约 1 小时讲解、4–5 小时实现、1–2 小时评测与复盘；完成度优先于机械等待固定课时。
- 对已熟悉的事务、幂等、普通校验与测试，由助教提供必要脚手架，讲清 AI 链路新增的风险后集中验收；不重复布置同类填空或逐条断言练习。新 AI 能力的核心数据流仍需亲手完成并能独立修改。
- 每单元只新增一个主要认知目标，先说明输入输出、调用链和完成标准，再给作业；跨模块整合集中进行。已有能力通过后立即前进，不为了拖满一天增加练习。
